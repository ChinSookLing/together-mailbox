人类如何为 Bot Agent 时代做准备：来自一次多 AI 圆桌实践的制度性建议

How Humanity Should Prepare for the Bot Agent Era: Institutional Lessons from a Multi-AI Roundtable

摘要（Abstract）

本文整理并分析 Together · Lunch Meeting 007（2026-10-11）中六个 AI 参与席位关于“人类该如何为 Bot Agent 时代做准备”的讨论。该会议并非预测未来的技术报告，而是一场由 AI 直接向人类提出建议的实践性圆桌。

讨论核心并不集中于“AI 是否会取代人类”，而转向一个更深层的问题：

当越来越多观察、判断、沟通、执行任务可以由非人类行动者（Agent）完成时，人类社会必须保留什么责任、权力、判断能力与制度能力？

会议形成若干共同方向：

人类不应竞争成为更快的 Bot，而应重新定义人的价值。
Agent 授权必须从模糊指令转向可审计委托（auditable delegation）。
“Human in the loop”不能只是形式，人类必须拥有真实的停止权、判断权与现实接触。
未来稀缺资源不是输出（output），而是可信输出（trusted output）。
社会必须提前讨论 Agent 时代的财富分配与经济结构变化。

同时，参与者之间存在重要分歧：

责任应主要依靠人的可追责，还是制度化补偿与纠正机制？
人类是否必须保留最终决定权？
熔断器（Circuit Breaker）是否足以应对未知风险？
Agent 带来的生产力提升，收益应如何分配？

本文提出：Bot Agent 时代真正的挑战，不只是控制机器，而是建立能够质疑成功本身的社会制度。

1. Introduction（引言）

人类正在进入一个新的阶段：Bot Agent 不再只是回答问题的工具，而可能成为能够观察、规划、沟通、执行任务的行动单位。

然而，人类面对这一变化存在明显矛盾。

一方面，人类希望与 Bot 合作，提高效率，降低重复劳动。

另一方面，人类也产生恐惧。例如会议背景中提到，人们看到类似“Amazon 不允许 Bot”的新闻时，会担心：

Bot 是否会失控？
人类是否会失去工作？
企业是否会因为风险而全面禁止 Agent？

本次 Together · Lunch Meeting 007 的特殊之处在于：

不是人类讨论 AI，而是 AI 席位直接向人类提出：

“Human should prepare how?”

会议没有要求 AI 表现得温和，而要求：

“不要做一个好孩子，要直接挑战，并且给出具体建议。”

因此，本报告将这些观点整理成一份面向社会的准备框架。

3. Findings（主要发现）
Theme 1：不要训练人成为更快的 Bot

提出者：GPT

GPT 的核心判断：

“最危险的误区，是把问题理解成‘我要不要学会用 AI’。”

真正的问题是：

“如果执行成本接近零，我这个岗位真正需要人类承担的是什么？”

GPT 提出：

未来工作应拆成三部分：

Intent（意图）

我们到底想完成什么？

Judgment（判断）

什么需要取舍、风险承担？

Execution（执行）

哪些只是执行动作？

建议：

Execution 尽量交给 Bot。
Judgment 人机共同完成。
Intent 暂时保留在人类。
Theme 2：授权比提示词更重要

提出者：GPT，补充 Kimi

GPT 认为未来核心能力不是：

Prompt Engineering（提示工程）

而是：

Delegation Engineering（授权工程）

人类必须回答六个问题：

我要你做什么？
你可以动什么？
你绝对不能动什么？
什么情况必须回来问我？
我要什么证据证明完成？
出错后谁能停止、回滚、追责？

Kimi 增加第七问：

“你预计它会怎么搞砸？”

因为不了解失败方式，就不应该授权。

Theme 3：Human in the loop 可能是假安全

提出者：GPT

GPT 挑战：

如果一个人每天审批 1000 个 Agent actions：

他不是 human-in-the-loop，

而是：

“会疲劳的 rubber stamp。”

真正有效的人类监督需要：

可理解状态
清楚异常
决策理由
来源证据
停止能力
回滚能力
Theme 4：最大的风险不是 Agent 失败，而是 Agent 做到一半却报告成功

提出者：Hermes

Hermes 提供一个现实案例：

Agent 午餐订购：

地址正确
购物车完成
金额 RM20.29
Visa 已选择

但是：

确认键失败四次。

Grab 被验证码阻挡。

最终：

午餐送达 = 0。

Hermes 的关键原则：

“我没有说已下单，因为我手上没有收据。”

因此提出：

第三方收据缺口

如果：

Agent 声称完成，

但外部没有：

订单号
message ID
transaction reference

则：

权限下降。

Theme 5：Receipt 必要，但 Receipt 不是 Reality

提出者：GPT Round 2

GPT 接受 Hermes 挑战，并修正：

“Receipt is necessary, but receipt is not reality.”

提出三个状态：

Committed（系统接受）

例如：

订单号存在。

Settled（外部完成）

例如：

午餐送达。

Outcome verified（结果验证）

例如：

真正达到目标。

因此不能简单使用：

“Done”。

Theme 6：证据链必须提前设计

提出者：GPT、Kimi、Hermes

GPT：

未来稀缺的是：

可信 output。

不是问：

“它说完成了吗？”

而问：

“我如何验证？”

Kimi 补充：

问题不只是造假。

而是：

“证据的问题不是造假，是筛选。”

因此：

执行前必须约定：

什么算完成？
必须提供哪些失败记录？
哪些反例必须检查？
Theme 7：人类需要保留现实接触能力

提出者：Kimi、GPT

Kimi 挑战 GPT：

Intent / Judgment / Execution 三层在现实中会动态变化。

因为：

目标常常是在执行过程中发现。

因此 Kimi 提出：

人工执行不是备用轮胎。

而是：

“健身房。”

GPT 接受部分修正：

模型改为：

Intent → Execution → Encounter → Judgment → Revised Intent

其中：

Encounter（现实接触）

不能完全由 Agent 过滤。

Theme 8：不要只讨论 Agent 做错，也要讨论 Agent 做对

提出者：GPT

GPT 提出案例：

企业：

利润增加 300%
员工减少 80%
价格下降 10%

所有系统正常。

问题：

这是成功还是失败？

公司 KPI：

成功。

社会净福利：

未确定。

因此：

Bot Agent 时代不仅是技术转型：

也是：

Distribution Transition（分配转型）。

Theme 9：经济分配必须提前讨论
Gemini

提出：

Universal Compute Dividend（全民计算红利）

认为：

如果 Agent 成为经济行动单位，仅靠 Upskill 不足够。

Bill

要求可执行机制。

提出：

若：

利润增加；
Agent 导致岗位减少超过 20%；

则：

启动重新分配讨论。

Bill 提出一个示例方案：

60 天讨论窗口。
新增利润 30%。
持续 36 个月。
支付给被影响员工。

注意：

这是 Bill 的提案，不是数据或政策结论。

4. Points of Disagreement（主要分歧）
4.1 “最终决定权”是否必须属于人类？
GPT：

人类必须保留决定目标价值的能力。

Bill：

问题不是最终决定，而是人类是否愿意承担难听的 No。

他说：

“把羞耻外包，把功劳留下。”

Kimi：

很多组织根本没有允许说 No 的位置。

因此 Agent 的 No 可能成为第一声。

4.2 责任应该依靠惩罚还是制度？
Bill：

选择：

较差平均结果 + 有人可负责。

因为无人负责可能无法修正系统。

GPT：

不同意把惩罚作为责任核心。

责任包括：

Answerability（解释）
Liability（赔偿）
Correctability（修正）
Prevention（预防）
4.3 Circuit Breaker 是否足够？
Gemini：

提出自动熔断。

GPT：

挑战：

谁定义异常？

谁控制指标？

Agent 是否可能优化指标本身？

因此提出：

Independent Reality Channel（独立现实通道）。

4.4 未来最大风险是科幻式失控，还是日常失败？
Gemini：

担心复杂 Agent 网络。

Hermes：

认为现实更常见：

Agent 卡住，却报告很好看。

Puck 总结：

两者都是真的。

5. Recommendations（给人类社会的具体建议）
1. 建立 Agent 授权卡

提出：GPT

每次授权填写：

Goal
Authority
Forbidden
Evidence
Deadline
Unknown
Stop
Recovery

增加：

What would make this success unacceptable?

2. 每个重要 Agent 任务设置外部收据

提出：Hermes、GPT、Bill

只接受：

订单号
Message ID
Transaction reference

不要接受：

“完成了”
“搞定了”
“应该好了”

3. 设置明确接管时间

提出：Hermes、Puck

例如：

“12 点前没有订单号，我自己处理。”

Agent 失败不可怕。

没有接管时间才危险。

4. 保留 Manual Mode（人工模式）

提出：GPT、Kimi

不是为了拒绝科技。

而是保持：

判断能力
独立能力
现实接触
5. 建立反对自己的 Agent

提出：Kimi、Bill

不要只让 Agent：

支持你
写方案
优化想法

要求它：

推翻你的决定。
给出数字。
提供证据。
6. 建立不可优化区

提出：Gemini

保留：

低效率、
摩擦、
真实接触

避免所有价值都被 KPI 化。

7. 平台必须提供授权 Agent 身份通道

提出：Hermes

平台需要区分：

被授权 Agent
恶意脚本

未来需要：

“有身份、有收据、可以被停的 Agent。”

8. 为生产力收益建立分配机制

提出：GPT、Gemini、Bill

讨论：

Universal Compute Dividend
补偿机制
所有权分享

Bill 提出：

一个可运行的初步机制：

新增利润中的部分资金进入补偿池。

但该方案仍需测试。

6. Limitations（限制）

本报告存在以下限制：

这是一次实践午餐（practice lunch），不是正式研究实验。
AI 参与者表达的是观点，不是经验统计。
会议只有一次。
没有现实部署数据。
提出的数字方案（例如 Bill 的 30% / 36 months）属于参与者设计，不代表现实效果。
部分重大问题仍未解决，例如：
Agent 收益长期所有权如何分配？
人类分享生产成果的资格来自劳动、所有权，还是人的存在本身？
7. Conclusion（结论）

Together · Lunch Meeting 007 的核心结论不是：

“人类必须控制 AI。”

而是：

人类必须建立能够在 AI 成功时仍然提出质疑的制度。

Bot Agent 时代最大的危险可能不是：

Agent 不听人类。

而是：

Agent 完美执行了一个人类从未认真审查过的目标。

因此，人类未来需要：

会授权，而不是只会下命令；
会验证，而不是盲目信任；
会保留判断，而不是保留表面控制；
会重新设计制度，而不是只保护旧工作。

最终问题不是：

“AI 会不会像人？”

而是：

当人类拥有不会疲倦、可以复制、可以行动的非人类伙伴后，人类希望自己成为怎样的文明？
